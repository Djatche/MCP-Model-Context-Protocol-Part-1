# MCP (Model Context Protocol)
Les LLM  ne connaissent que les informations auxquelles ils ont été exposés pendant la phase d’entrainement. Ils n’ont donc pas accès aux données en temps réel ou aux données externes. Les LLM ont donc besoin des API pour accéder à ces types de données et accroitre leur capacité. Mais l’intégration des API est complexe. Chaque outil ou API nécessite un développement spécifique pour se connecter au système d’IA. 
Le secteur de l’IA a besoin d’une méthode unique et standardisé permettant aux systèmes d’IA d’accéder aux fonctionnalités externes.
 Le MCP « Model Context Protocol »  facilite l’intégration d’application IA aux systèmes environnants. C »est une sorte de port USB-C pour les applications d’IA. Le MCP simplifie la connectivité et ajoute des fonctionnalités absentes des API traditionnelles. Le LLM peut identifier, en temps réel et lors du traitement d’une requête, les outils proposés par un serveur MCP.
Le présent article va présenter un MCP avant l’intégration d’un modèle de LLm. On utilisera l’architecture MCP : hôte, client et serveur. Nous présenterons un exemple des trois types de primitives tool, resource et prompt.
-	Ce MCP permettra à une application IA d’estimer la quantité de vaccins polio oral pour une campagne de vaccination.
-	Il expose un modèle de prompt ainsi que une resource (valeur par défaut des paramètres). ils peuvent s’assembler pour créer un contexte pour le LLM.
-	Il expose aussi un tool qui estime la quantité de vaccins nécessaire pour une localité en se basant sur la population totale, la proportion des enfants de moins de cinq ans, la couverture vaccinale visée, le stock de sécurité, le taux de perte ainsi que le nombre de doses de vaccins par flacons. Toutes ces données exceptées la population de la localité ont des valeurs par défaut exposées par le MCP via sa resource aux IA.
